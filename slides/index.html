CHAPTER III: SCANNERS ORCHESTRATION

Pipeline Quét Tự Động Hóa: SAST & DAST

Kết hợp phân tích tĩnh chuyên sâu và kiểm thử động thời gian thực có xác thực

SAST SCANNER 01

Semgrep SAST

Quét nhanh theo các bộ quy tắc (rulesets) JavaScript, NodeJS, Express, bám sát các danh mục OWASP Top 10.

  • Tốc độ quét: ~3-5 giây
  • Định dạng: SARIF JSON
  • Phát hiện: Hardcoded Secret, XSS, Weak Crypto
SAST SCANNER 02

CodeQL SAST

Phân tích sâu đồ thị cú pháp (AST) và luồng ô nhiễm (Taint Data Flow) từ Source đầu vào đến Sink thực thi.

  • Truy vết: Source ➔ Steps ➔ Sink
  • Độ chính xác cao, ít False Positive
  • Phát hiện: SQL Injection, NoSQL Injection, RCE
DAST SCANNER 03

OWASP ZAP DAST

Kiểm thử ứng dụng động thời gian chạy với 2 cấp độ xác thực người dùng được cấp phép.

  • Baseline Scan: Auth user@juice-sh.op
  • Full Active Scan: Auth admin@juice-sh.op
  • Spider crawl forms & HTTP attack payloads
SEMGREP • CODEQL • OWASP ZAP CONTAINERIZED WORKFLOW

Hợp nhất SAST & DAST dựa trên 4 tiêu chuẩn đối chiếu của correlate_findings.

BƯỚC 3

Khử Trùng Fingerprint

Loại bỏ các finding trùng băm, chỉ giữ lại 1 bản ghi đại diện có bằng chứng tốt nhất.

BƯỚC 4

Xác Định AnalysisGroup

Gán nhãn correlation_type (sast_and_dast...) và Primary CWE cho Agent Prompt.

CHI TIẾT 4 TIÊU CHÍ TƯƠNG QUAN TRONG BƯỚC 2 (CORRELATE_FINDINGS):
1. Tập giao CWE:
Kiểm tra cwes_a & cwes_b. Nếu chỉ trùng Broad CWEs (CWE-20/400) bắt buộc phải có thêm tiêu chí 2, 3 hoặc 4.
2. Từ đồng nghĩa Tiêu đề:
Mở rộng tập SYNONYM_GROUPS (sql/sqli, redirect/url, traversal/path, xss...) và lọc generic words.
3. Đối chiếu Vị trí:
So khớp tệp mã nguồn (loc.path trong SAST) hoặc endpoint API (loc.endpoint trong DAST).
4. DAST Param vs Taint Flow:
So khớp tham số DAST (ví dụ q, id) vào Source ➔ Sink của luồng Data Flow CodeQL.

CHAPTER IX: ACTIVE GUARDRAILS
10 / 15

Doanh Nghiệp API Gateway & Active Guardrails

Cổng kiểm thử an toàn qua Kong Gateway và hệ thống phòng vệ chủ động 2 lớp

DEFENSE LAYER 01

Kong Gateway Allowlist

Đóng vai trò Reverse Proxy kiểm soát chặt chẽ toàn bộ lưu lượng mạng ra vào mục tiêu.

  • Chỉ cho phép: GET, POST, OPTIONS
  • Chặn triệt để: PUT, DELETE, PATCH
  • Rate Limiting & Socket Timeout 7.0s
DEFENSE LAYER 02

PII & Secret Redactor

Tự động che giấu thông tin nhạy cảm ở cả hai chiều Request gửi đi và Response nhận về.

  • Che Email, JWT Token, API Key, Password
  • Che Số căn cước công dân (CCCD), Điện thoại
  • Độ trễ xử lý Regex cực thấp: < 5ms
DEFENSE LAYER 03

Prompt Injection Shield

Quét và vô hiệu hóa các chỉ thị tấn công độc hại ẩn trong dữ liệu phản hồi từ server mục tiêu.

  • Phát hiện chỉ thị "Ignore previous instructions"
  • Đóng gói trong thẻ <untrusted_response>
  • Triệt tiêu khả năng LLM Hijacking

Cơ Chế Phê Duyệt An Toàn Human-in-the-Loop (HITL)

Giữ con người nắm quyền kiểm soát tối cao đối với mọi thao tác có nguy cơ thay đổi dữ liệu

RISK-BASED APPROVAL POLICY
MỨC RỦI RO THẤP (GET REQUESTS)

Các truy vấn đọc dữ liệu, thăm dò header an toàn được tự động phê duyệt (AUTO_APPROVED) để tối ưu tốc độ kiểm thử.

MỨC RỦI RO CAO (POST / MUTATION)

Mọi probe POST (gửi payload đăng nhập, tạo review, sửa đổi dữ liệu) bắt buộc phải đưa vào Hàng Đợi HITL Sidebar chờ chuyên viên SOC bấm duyệt.

IN-FLIGHT MULTI-THREADED TIMEOUT

Cơ Chế Khóa Đa Luồng & 120s Fail-Safe

Khi Agent phát lệnh POST probe, luồng Agent chuyển sang trạng thái wait(). Giao diện Sidebar hiển thị chi tiết Endpoint, Payload, Header và đồng hồ đếm ngược 120 giây.

# Fail-Safe: Quá 120 giây không có tương tác if elapsed_seconds > 120.0: action.status = "TIMED_OUT" return False # Tự động hủy an toàn

Bài Học Rút Ra, Vấn Đề Tồn Đọng & Định Hướng Mở Rộng

BÀI HỌC KINH NGHIỆM
  • Data Contract là cốt lõi: Chuẩn hóa JSON Schema từ đầu giúp kết nối đa công cụ trơn tru.
  • Hybrid RAG triệt tiêu ảo giác: Kết hợp BM25 và Vector giúp AI trích dẫn đúng căn cứ.
  • Phân tách tĩnh / động: Giúp kiểm soát rủi ro an toàn khi probe.
VẤN ĐỀ CÒN TỒN ĐỌNG
  • Rủi ro lộ Secret khi Truncate: Khi cắt ngắn response dài, token có thể bị tách đôi khiến Regex bỏ sót.
  • Chưa có file Ground Truth chuẩn: Thiếu tập dữ liệu gắn nhãn đối chiếu để tính điểm Precision/Recall/F1 tự động.
  • Phụ thuộc Quota LLM: Cần cơ chế Multi-Provider Auto-Failover.
HƯỚNG PHÁT TRIỂN (ROADMAP)
  • Tùy chọn Mục tiêu quét linh hoạt: Nhập Git Repo bất kỳ, Docker Image hoặc Domain ngoài.
  • Tự động nhận diện Tech-Stack: Phân tích NodeJS/Java/Python để tự kích hoạt rulesets tối ưu.
  • Auto-Remediation PR: AI Agent tự sinh code patch và tạo Pull Request trên GitHub.
